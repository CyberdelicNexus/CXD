**Part A: Add retry with exponential backoff to save()**

After the read-merge-write save (from Plan 01-01), if the save fails due to a network error (TypeError: Failed to fetch), retry up to 3 times with exponential backoff (1s, 2s, 4s). Do NOT retry on RLS/permission errors (code 42501) — those are permanent failures.

Add a `private failedSaves: number` counter. If it exceeds 5 consecutive failures, emit a warning event that the UI can listen to.

```typescript
// Add to SupabasePersistence class:
private consecutiveFailures = 0;
private onPersistenceError?: (error: string) => void;

// Add to constructor params:
constructor(doc: Y.Doc, projectId: string, opts?: { onError?: (error: string) => void }) {
  // ...existing...
  this.onPersistenceError = opts?.onError;
}
```

In `save()`, after a failed save:
- Increment `consecutiveFailures`
- If `consecutiveFailures >= 5`, call `this.onPersistenceError?.('Save failed 5 times consecutively. Your changes are safe locally but not yet synced to the cloud.')`
- On successful save, reset `consecutiveFailures = 0`

For network errors specifically, schedule a retry:
```typescript
private scheduleRetry(attempt: number): void {
  if (attempt >= 3) return; // max 3 retries
  const delay = Math.pow(2, attempt) * 1000; // 1s, 2s, 4s
  setTimeout(() => this.save(), delay);
}
```
