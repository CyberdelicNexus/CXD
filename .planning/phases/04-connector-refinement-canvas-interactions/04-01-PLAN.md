  <name>Task 1: Fix connector z-order rendering</name>
  <files>src/components/cxd/cxd-canvas.tsx</files>
  <action>
The connector SVG layer currently has a fixed `zIndex: 5` (line ~3630) while all canvas elements render in a container with `zIndex: 10` (line ~3381). This means ALL connectors render BELOW ALL elements -- the opposite of the requirement.

**Fix approach: Per-edge z-index based on connected element z-indices.**

Instead of rendering all edges in a single SVG layer below all elements, render each edge's SVG individually at a z-index that places it above its connected elements but below unrelated higher-z elements.

1. Remove the single SVG wrapper div with `zIndex: 5` that holds all edges (lines ~3624-3835).

2. Move edge rendering into the same parent container that holds canvas elements (the `zIndex: 10` div starting at line ~3376). For each edge, create an absolutely-positioned SVG element that renders at a z-index computed as:
   ```
   connectedMaxZ = Math.max(fromElement.zIndex, toElement.zIndex)
   edgeZIndex = connectedMaxZ + 0.5
   ```
   This places the connector above both connected elements but below any unrelated element with a higher zIndex.

3. Each edge SVG should be `pointer-events: none` on the wrapper, with `pointer-events: auto` and `cursor: pointer` on the invisible click-target path only (preserving current click-to-select behavior).

4. Keep the connector preview line (shown during connector creation, lines ~3807-3831) in a separate absolutely-positioned SVG at a high z-index (e.g., 9998) so it always renders on top during drawing.

5. Keep the bend/anchor handles for selected edges (lines ~3837+) at their current high z-index so they remain interactive.

**Important:** Do NOT change the LineLayer (line-layer.tsx) rendering -- that's for free-floating lines (not connectors). Only change the CanvasEdge rendering in cxd-canvas.tsx.

**Important:** The SVG for each edge needs `overflow: visible` and sufficient width/height (use the same approach as current: `width: 10000px, height: 10000px`), or better yet, use `width: 1, height: 1` with `overflow: visible` since the SVG paths use absolute world coordinates anyway. Keep `position: absolute, left: 0, top: 0` on each edge SVG.

2. The anchor position calculation uses the element's actual x/y/width/height. If an edge's anchor point visually appears to overlap into the card body, the issue is likely that the card's rendered border/padding creates a visual offset from the element's geometric bounds. Fix: Add a small inset offset (e.g., 2px) to `getAnchorPosition()` results in cxd-canvas.tsx when computing `from` and `to` points in `getResolvedEdgePoints`. This means for `top` anchor, y becomes `element.y + 2`; for `bottom`, `element.y + height - 2`; for `left`, `element.x + 2`; for `right`, `element.x + width - 2`. Apply this offset ONLY in the resolved points used for rendering, not in the type utility function itself.

3. When creating new edges (in the connector creation flow, ~line 1186 and ~line 1897), ensure `fromAutoAnchor: true` and `toAutoAnchor: true` are set so edges automatically pick the best side. Check the edge creation code and confirm these flags are being set.

<task type="auto">
  <name>Task 3: Add always-visible circular midpoint node on connected edges</name>
  <files>src/components/cxd/cxd-canvas.tsx</files>
  <action>
Every connected edge (CanvasEdge with fromNodeId + toNodeId) should display a small circular node at the bend/midpoint position — always visible, not just when the edge is selected or hovered. This node replaces/augments the existing hidden drag handle and makes bend-point repositioning discoverable.

**Visual design (match the screenshots — colored ring, dark fill):**
- Outer circle: `r=7`, fill = edge stroke color (e.g., `#a78bfa` for default purple), opacity 0.9
- Inner circle: `r=4.5`, fill = `#0f0f0f` (near-black, matching dark canvas background)
- This creates a colored ring with dark center effect
- On hover: outer circle expands slightly (`r=8.5`), add `filter: drop-shadow(0 0 4px <strokeColor>)`
- On the selected edge: ring gets a white outer ring (`r=9`, stroke white 1.5px, fill none)

**Positioning:**
- If the edge has an explicit bend point (`edge.bend`), render the circle there
- If no explicit bend (`!edge.bend`), compute the geometric midpoint of the quadratic bezier curve and render there:
  ```typescript
  // Midpoint of quadratic bezier at t=0.5
  const midX = 0.25 * fromPt.x + 0.5 * bendPt.x + 0.25 * toPt.x;
  const midY = 0.25 * fromPt.y + 0.5 * bendPt.y + 0.25 * toPt.y;
  ```
  where `bendPt` is the computed bend (midpoint of from+to if no explicit bend).

**Drag behavior (reuse existing bend drag logic):**
- The circle node is the new drag target for repositioning the bend.
- `onMouseDown` on the circle should start a drag that updates `edge.bend` via `syncUpdateEdge` — same logic as the existing bend handle drag.
- After drag, if the user drops the node near the geometric midpoint (within 10px), clear the explicit bend (`syncUpdateEdge(edge.id, { bend: undefined })`) so it returns to auto-centering.

**Rendering location:**
- Render the circle node INSIDE each per-edge SVG (from Task 1), at the same z-level as the edge itself.
- Use `pointer-events: none` on the SVG wrapper, `pointer-events: auto` on the circle elements only.
- The node should appear on ALL connected edges — not just selected ones.

**Implementation in cxd-canvas.tsx:**
Add a `MidpointNode` sub-render inside the per-edge rendering loop (after the path elements):

```tsx
{/* Midpoint circle node — always visible on connected edges */}
{(() => {
  const [resolvedFrom, resolvedBend, resolvedTo] = getResolvedEdgePoints(edge, elementsById);
  const nodeX = !edge.bend
    ? 0.25 * resolvedFrom.x + 0.5 * resolvedBend.x + 0.25 * resolvedTo.x
    : resolvedBend.x;
  const nodeY = !edge.bend
    ? 0.25 * resolvedFrom.y + 0.5 * resolvedBend.y + 0.25 * resolvedTo.y
    : resolvedBend.y;
  const isNodeHovered = hoveredMidpointEdgeId === edge.id;
  const isSelected = selectedEdgeId === edge.id;
  return (
    <g
      style={{ pointerEvents: 'auto', cursor: 'grab' }}
      onMouseDown={(e) => startBendDrag(e, edge)}
      onMouseEnter={() => setHoveredMidpointEdgeId(edge.id)}
      onMouseLeave={() => setHoveredMidpointEdgeId(null)}
    >
      {isSelected && (
        <circle cx={nodeX} cy={nodeY} r={9} fill="none" stroke="white" strokeWidth={1.5} />
      )}
      <circle
        cx={nodeX} cy={nodeY}
        r={isNodeHovered ? 8.5 : 7}
        fill={strokeColor}
        opacity={0.9}
        style={{ filter: isNodeHovered ? `drop-shadow(0 0 4px ${strokeColor})` : undefined }}
      />
      <circle cx={nodeX} cy={nodeY} r={4.5} fill="#0f0f0f" />
    </g>
  );
})()}
```

Add `hoveredMidpointEdgeId` state: `const [hoveredMidpointEdgeId, setHoveredMidpointEdgeId] = useState<string | null>(null);`

Extract a `startBendDrag(e, edge)` helper from the existing bend drag logic so both the old handle (for selected edges) and the new always-visible node share the same drag implementation.
