<task type="auto">
  <name>Task 1: Fix connector z-order rendering</name>
  <files>src/components/cxd/cxd-canvas.tsx</files>
  <action>
The connector SVG layer currently has a fixed `zIndex: 5` (line ~3630) while all canvas elements render in a container with `zIndex: 10` (line ~3381). This means ALL connectors render BELOW ALL elements -- the opposite of the requirement.

**Fix approach: Per-edge z-index based on connected element z-indices.**

Instead of rendering all edges in a single SVG layer below all elements, render each edge's SVG individually at a z-index that places it above its connected elements but below unrelated higher-z elements.

1. Remove the single SVG wrapper div with `zIndex: 5` that holds all edges (lines ~3624-3835).

2. Move edge rendering into the same parent container that holds canvas elements (the `zIndex: 10` div starting at line ~3376). For each edge, create an absolutely-positioned SVG element that renders at a z-index computed as:
   ```
   connectedMaxZ = Math.max(fromElement.zIndex, toElement.zIndex)
   edgeZIndex = connectedMaxZ + 0.5
   ```
   This places the connector above both connected elements but below any unrelated element with a higher zIndex.

3. Each edge SVG should be `pointer-events: none` on the wrapper, with `pointer-events: auto` and `cursor: pointer` on the invisible click-target path only (preserving current click-to-select behavior).

4. Keep the connector preview line (shown during connector creation, lines ~3807-3831) in a separate absolutely-positioned SVG at a high z-index (e.g., 9998) so it always renders on top during drawing.

5. Keep the bend/anchor handles for selected edges (lines ~3837+) at their current high z-index so they remain interactive.

**Important:** Do NOT change the LineLayer (line-layer.tsx) rendering -- that's for free-floating lines (not connectors). Only change the CanvasEdge rendering in cxd-canvas.tsx.

**Important:** The SVG for each edge needs `overflow: visible` and sufficient width/height (use the same approach as current: `width: 10000px, height: 10000px`), or better yet, use `width: 1, height: 1` with `overflow: visible` since the SVG paths use absolute world coordinates anyway. Keep `position: absolute, left: 0, top: 0` on each edge SVG.

**Edge-snapping (CON-01):**

The current `getAnchorPosition()` correctly returns the midpoint of the element's edge. However, verify that:

1. When `fromAutoAnchor` or `toAutoAnchor` is true on an edge, the `getClosestAnchors()` function properly determines the nearest cardinal side. This currently uses center-to-center comparison which is correct for auto-anchor.

2. The anchor position calculation uses the element's actual x/y/width/height. If an edge's anchor point visually appears to overlap into the card body, the issue is likely that the card's rendered border/padding creates a visual offset from the element's geometric bounds. Fix: Add a small inset offset (e.g., 2px) to `getAnchorPosition()` results in cxd-canvas.tsx when computing `from` and `to` points in `getResolvedEdgePoints`. This means for `top` anchor, y becomes `element.y + 2`; for `bottom`, `element.y + height - 2`; for `left`, `element.x + 2`; for `right`, `element.x + width - 2`. Apply this offset ONLY in the resolved points used for rendering, not in the type utility function itself.

3. When creating new edges (in the connector creation flow, ~line 1186 and ~line 1897), ensure `fromAutoAnchor: true` and `toAutoAnchor: true` are set so edges automatically pick the best side. Check the edge creation code and confirm these flags are being set.

**Visual polish (CON-04):**

1. Add `strokeLinecap="round"` and `strokeLinejoin="round"` to the visible path element for smoother curve rendering.

2. Adjust the arrow marker `refX` from 9 to 8 so the arrowhead doesn't extend past the endpoint, creating a cleaner attachment point.

3. Add a subtle glow effect to the connector when hovered (not just selected). Add an `onMouseEnter`/`onMouseLeave` hover state on the invisible click-target path, and apply a subtle `filter: drop-shadow(0 0 3px <strokeColor>)` on hover.
